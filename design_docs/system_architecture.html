1. Architectural Goals

CareerVector separates offline corpus/model construction from online recommendation. RAG extends the runtime path without changing the underlying dataset or requiring a vector database.

3. RAG Runtime Boundary

flowchart LR APP[CareerVector process] --> RET[Embedding retriever] RET --> EV[Retrieved evidence] APP --> CLIENT[OllamaClient] CLIENT --> API[localhost:11434 api chat] API --> LLM[Local model] LLM --> API API --> CLIENT CLIENT --> APP
The Ollama server is a local process boundary. CareerVector does not import an Ollama orchestration framework; it uses the REST API directly.

6. Repository Responsibilities

ModuleResponsibility
rag/context.pyTransforms retrieved result dictionaries into bounded, citation-addressable evidence blocks.
rag/prompts.pyDefines grounding rules and builds the user-profile plus evidence prompt.
rag/ollama.pyLists installed local models and calls /api/chat with non-streaming requests.
rag/service.pyCoordinates retrieval, context construction, prompt construction, generation, and response packaging.
app.pyThree-mode UI, local model selection, error feedback, generated answer rendering, and evidence inspection.
