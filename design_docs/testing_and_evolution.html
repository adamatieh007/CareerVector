2. Unit-Test Targets

AreaRepresentative checks
Profile parsingOptional fields, list normalization, salary values, empty input handling.
Text constructionTF-IDF weighting and semantic query formatting remain deterministic.
TF-IDF scoringKnown lexical matches rank above unrelated occupations.
Embedding scoringDense matrix dimensions, normalization, ranking order, avoid penalties.
ConstraintsMinimum salary correctly removes records lacking the required wage threshold.
ArtifactsHelpful errors are produced when required generated files are missing.

3. Retrieval Evaluation

Model quality should be measured on a curated set of profiles with one or more acceptable occupation targets. TF-IDF and embeddings must be evaluated on the same profiles and corpus.

flowchart LR P[("evaluation_profiles.json")] --> T["TF-IDF"] P --> E["Embeddings"] T --> MT["Recall@K<br/>MRR<br/>NDCG"] E --> ME["Recall@K<br/>MRR<br/>NDCG"] MT --> C["Compare"] ME --> C C --> FA["Failure analysis"]

4. Metrics

MetricWhy it matters
Recall@KWhether at least one expected occupation appears in the top recommendations.
MRRRewards retrieving a relevant occupation near the very top of the ranking.
NDCG@KUseful once evaluation profiles contain multiple acceptable careers with graded relevance.
LatencyCaptures UX cost of TF-IDF versus embedding inference.
Overlap@KShows how often the two retrieval engines agree.

7. RAG Boundary

Sentence embeddings alone are retrieval, not RAG. A future RAG layer should retrieve occupation evidence first and pass only that grounded evidence to a local language model for explanation. Ranking should remain independently testable.

flowchart LR P["Profile"] --> RET["Retriever"] RET --> K["Top occupations + O*NET evidence"] K --> LLM["Local LLM"] LLM --> EX["Grounded explanation"] K --> UI["Ranked result metadata"] EX --> UI

8. Release Checklist

  • Run unit tests.
  • Rebuild corpus when source-data version changes.
  • Regenerate both model artifacts from the same processed corpus.
  • Run evaluation for both engines and save benchmark results.
  • Verify no raw datasets, virtual environments, model caches, or generated artifacts are accidentally committed.
  • Update design docs when model contracts or pipeline boundaries change.
