Purpose

These documents describe the current CareerVector application and the intended design direction as the project grows from a lexical TF-IDF baseline into a semantic recommendation platform. The documentation deliberately separates data ingestion, retrieval, presentation, and evaluation so each subsystem can evolve independently.

1. System Architecture

Top-level components, module responsibilities, runtime boundaries, artifact layout, and end-to-end control flow.

2. Data Pipeline

How O*NET and BLS data are downloaded, normalized, joined, weighted, transformed, and persisted.

3. Retrieval Engines

Detailed TF-IDF and sentence-embedding designs, scoring behavior, avoidance penalties, and salary filtering.

4. UI & Request Flow

Streamlit interaction design, frontend model selection, request validation, ranking, and result rendering.

5. Testing & Evolution

Unit/evaluation strategy, model-comparison metrics, failure analysis, and the roadmap toward hybrid retrieval and RAG.

Design Principles

  • Reproducible: raw government data is downloaded and transformed by scripts rather than manually edited.
  • Local-first: ranking runs locally; no paid inference API is required.
  • Comparable: TF-IDF and embeddings operate over the same occupation corpus so evaluation is meaningful.
  • Explainable: recommendations preserve occupation metadata, related titles, wage information, and model-specific evidence.
  • Extensible: UI, retrieval engine, and corpus-building logic remain separated to support hybrid search and future RAG.
