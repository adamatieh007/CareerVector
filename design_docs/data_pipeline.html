Data Pipeline

Detailed design for transforming O*NET and BLS data into a shared retrieval corpus.

1. Source Data

CareerVector uses O*NET as the semantic occupation knowledge base and BLS OEWS data as the wage source. Raw data remains external to Git and is regenerated through scripts/download_data.py.

O*NET

Occupation descriptions, alternate titles, tasks, skills, knowledge, interests, work activities, and software/technology signals.

BLS OEWS

Occupation wage statistics joined to O*NET records through normalized SOC identifiers.

2. Data Transformation Pipeline

flowchart TD ON["O*NET tables"] --> N["Normalize columns and O*NET-SOC identifiers"] BLS["BLS OEWS"] --> NB["Normalize SOC identifiers + numeric wages"] N --> J["Group child tables by occupation"] J --> W["Build weighted occupation features"] NB --> M["Join wage metadata"] W --> M M --> C["Construct processed occupation row"] C --> OUT[("data/processed/occupations.csv")] OUT --> TF["TF-IDF training"] OUT --> EMB["Sentence embedding build"]

3. Occupation Record

Each processed row acts as the canonical retrieval record. It should preserve both human-readable metadata and model-ready text.

classDiagram class OccupationRecord { +string onet_soc_code +string title +string description +string alternate_titles +string interests +string skills +string knowledge +string work_activities +string core_tasks +string technologies +float median_wage +float mean_wage +string weighted_document +string semantic_document }

4. Weighted TF-IDF Document

TF-IDF benefits from explicit lexical weighting. Important concepts can be repeated or otherwise emphasized in the document representation so that high-value occupation features contribute more strongly to sparse similarity. 

occupation: Computer Hardware Engineers

title signals:
FPGA Engineer
ASIC Design Engineer
Embedded Hardware Engineer

high-weight interests:
engineering engineering engineering
electronics electronics electronics

high-weight knowledge:
computers and electronics
engineering and technology

skills:
systems analysis
mathematics
critical thinking

tasks:
design new computer hardware
test computer hardware
...

5. Semantic Embedding Document

Dense embeddings should receive natural, non-repetitive text. The semantic document therefore preserves the same underlying evidence while presenting it as structured language rather than TF-frequency weighting. 

Career: Computer Hardware Engineers

Description: Research, design, develop, or test computer equipment...

Related job titles: FPGA Engineer, ASIC Design Engineer,
Embedded Hardware Engineer...

Interests: Engineering, Electronics...
Skills: Systems Analysis, Mathematics...
Knowledge: Computers and Electronics...
Core tasks: Design new computer hardware...

6. Salary Join

flowchart LR O["O*NET-SOC<br/>17-2061.00"] --> X["Normalize"] X --> S["SOC<br/>17-2061"] B["BLS SOC<br/>17-2061"] --> J{"Join"} S --> J J --> W["Median / Mean Wage"]

Wage values are metadata and constraints, not semantic text. A salary such as $120,000 should filter or re-rank candidates after relevance scoring instead of becoming a TF-IDF token or embedding phrase.
